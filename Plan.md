# План тестирования мобильного приложения «Мобильный хоспис»

## 1. Описание приложения
Приложение "Мобильный хоспис" предоставляет функционал по работе с новостями хосписа и включает в себя:

* новостную ленту хосписа
* информацию о новостях и функционал для работы с ними
* тематические цитаты
* информацию о приложении

## 2. "Границы" приложения

Приложение состоит из:

1. Страница авторизации

* Поле ввода **Логин**
* Поле ввода **Пароль**
* Кнопка **ВОЙТИ**
  
2. Главная страница приложения
   
* Строка меню приложения:
     * Гамбургер-меню:
       1. Главная
       2. Новости
       3. О приложении
     * Иконка бабочка (тематические цитаты)
     * Иконка пользователя (выход из учетной записи)
* Новостная лента

## 3. Виды тестирования

   * **Функциональное тестирование** - необходимо протестировать самые главные функции приложения, такие как авторизация, навигация между разделами, создание и редактирование новостей. Данный вид тестирования поможет выявить критические ошибки в работе приложения.

   * **Тестирование пользовательского интерфейса (UI Testing)** - необходимо провести тестирование корректности работы интерактивных элементов (кнопок, форм, меню). Данный вид тестирования выявит логические дефекты при различных сценариях использования.

   * **Исследовательское тестирование** - данный вид тестирования поможет выявить неожиданные ошибки или проблемы в системе, которые могли остаться незамеченными в рамках стандартного тестирования. Это может быть полезно на всех этапах разработки, но особенно эффективно, когда продукт уже близок к завершению и нужно понять, как он будет вести себя в реальных условиях.

## 5. Процесс тестирования

1. Страница авторизации
  * Авторизация с валидными логином и паролем
  * Авторизация с невалидными логином и паролем

2. Главная страница приложения
  * Раздел "Главная"
  * Раздел "Новости"
  * Раздел "О приложении"
  * Открытие пользовательского соглашения в разделе "О приложении"
  * Открытие политики о конфиденциальности в разделе "О приложении"
  * Раздел с мотвационными цитатами
  * Выход из учётной записи

3. Тестирование раздела Новости
  * Сортировка новостей (по дате публикации) в новостной ленте
  * Фильтр новостей по категориям и периоду публикации в новостной ленте
  * Раскрытие описания новости в новостной ленте
  * Создание новости (заполненные обязательные поля) в панели управления
  * Создание новости (пустые поля) в панели управления
  * Удаление существующей новости в панели управления
  * Раскрытие описания новости в панели управления
  * Редактирование существующей новости в панели управления
  * Сортировка новостей (по дате публикации) в панели управления
  * Смена статуса новости с "Активна" на "Не активна" в панели управления
  * Фильтр новостей по категориям,периоду публикации и активности в панели управления
  * Отображение новости с датой публикации соответствующей текущей в новостной ленте
  * Отображение новости с датой публикации не соответствующей текущей в новостной ленте

## 8. Инструменты для автоматизированного тестирования

- **Android Studio** - официальная интегрированная среда разработки (IDE) для создания приложений на платформе Android.
- **Espresso** - фреймворк для автоматизированного тестирования пользовательского интерфейса мобильных приложений на платформе Android.
- **Gradle** - система автоматизации сборки проектов, которая позволяет управлять зависимостями, компилировать и тестировать код, а также выполнять другие задачи в процессе разработки программного обеспечения. 
- **Java 11** - версия языка программирования Java, которая пользуется широкой популярностью в индустрии для разработки Android-приложений. Для тестировщиков JDK 11 важно тем, что предоставляет обширную экосистему библиотек и фреймворков, которые облегчают процесс тестирования приложений и сказывается на быстродействии тестируемых приложений, а также упрощает их поддержку и масштабирование, что критично для тестирования в условиях изменяющихся требований и новых функциональных возможностей.
- **JUnit4** - фреймворк для автоматического юнит-тестирования приложений на языке Java. Он содержит специальные функции и правила, которые позволяют легко писать и запускать тесты.
- **Record Espresso Test** - инструмент, который автоматически записывает действия пользователя для создания тестов.
- **Allure Framework** - это открытый инструмент для создания детальных и понятных отчётов о выполнении тестов. Allure предоставляет результаты тестирования в формате, понятном всем участникам процесса разработки, от тестировщиков до менеджеров проектов.

## 10. Риски при автоматизации тестирования

Не все сценарии могут быть автоматизированы по причине:

* Наличия ошибок в приложении
* Возможной сложности нахождения идентификаторов элементов
* Переименования, добавление или удаление элементов и разделов
* Смены идентификаторов элементов или обновления приложения 
* Изменения данных авторизации в приложении
